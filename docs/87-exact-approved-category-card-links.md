# 87｜已核准分類的資訊卡／詳情頁連結必須精確可比對

## 問題與真實邊界
PR #96 已讓首頁分類選單排除前後空白、控制字元、NFKC 轉換後危險符號等不能進行精確比對的來源標籤；但音檔卡及兩種詳情頁仍使用會 trim 的外部路由解析函式。如果 API 標籤是 `" 新人 "`，會產生值為 `"新人"` 的假可用連結，首頁精確篩選無法比對原卡。

## 最小修正
- 新增 `approvedExactCategoryLink`，以現有安全路由規則核驗來源原字串、拒絕任何導致標籤改寫的 trim；NFKC 後若轉成不安全字元亦拒絕。
- 首頁既有安全分類選單、資訊卡與訪客／verified-public 詳情共用核對。不可點擊者仍保留原標籤的純文字顯示；外部路由接受一般空白的既有相容性不變。
- 合成回歸測試涵蓋精確中文、全形 ＡＩ、前後空白、控制字元、全形危險括號、長標籤以及三個 UI 入口。
